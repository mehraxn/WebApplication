# Exercise: Semantic Page Layout

## Goal
Build a single HTML page that uses the main semantic layout tags to structure a
simple blog-style site: `header`, `nav`, `main`, `section`, `article`, `aside`,
and `footer`.

## Concepts practiced
- Semantic HTML structure instead of plain `<div>`s
- Correct use of `<header>` and `<footer>` for top/bottom content
- `<nav>` for navigation links
- One `<main>` per page for the unique content
- `<section>` for grouped content and `<article>` for self-contained posts
- `<aside>` for related, secondary content
- Heading hierarchy (`h1` → `h2` → `h3`)

## Files included
- `index.html` — the semantic page layout
- `README.md` — this file

## What I learned
- Each semantic tag describes *what the content is*, which helps screen readers,
  SEO, and other developers.
- There should be only one `<main>` per page, and it shouldn't repeat the header,
  nav, or footer.
- `<article>` is for content that stands alone; `<section>` groups related content
  under a heading.
- A clean heading order acts like an outline of the page.
